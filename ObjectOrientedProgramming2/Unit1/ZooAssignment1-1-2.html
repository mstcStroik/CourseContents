Zoo 1.1, Part 2: Booth Items and Inventory

ASP.NET Core web app version

In this part, you will create the item classes used by the zoo's ticket booth, then populate the booth with inventory. The web app does not need to sell the items yet. That behavior comes in Part 3.

Topics Covered

  • Class creation from a diagram
  • Fields and properties
  • Constructor initialization
  • Lists of objects
  • Loops
  • DateTime
  • Encapsulation through object state

OOP reminder: Encapsulation means an object protects and manages its own data. A booth should own its inventory. Other code should ask the booth to do work instead of reaching directly into its lists.

1. Create the Booth Items Project

  1. Create a class library project named Zoo.BoothItems.
  2. Add references to this project from any project that needs to create or use booth items.
  3. Use the namespace Zoo.BoothItems for all booth item classes.

Check Your Work

  • Zoo.BoothItems exists in the solution.
  • The project builds successfully before classes are added.

2. Create the Booth Item Classes

Create these classes in Zoo.BoothItems:

  • CouponBook
  • Map
  • Ticket
  • WaterBottle

Class Requirements

  • CouponBook should store date made, date expired, and weight.
  • Map should store date issued and weight.
  • Ticket should store redeemed status, price, serial number, and weight.
  • WaterBottle should store price, serial number, and weight.

Constructor Requirements

  1. Initialize all fields in each constructor.
  2. Use get-only properties for values that outside code can read but should not freely change.
  3. For Ticket, add a Redeem method that can mark the ticket as redeemed.

Encapsulation check: Do not make fields public just because another class needs to read a value. Use properties to expose only the information that should be visible.

Check Your Work

  • Zoo.BoothItems builds successfully.
  • The full solution builds successfully.

3. Add Booth Item Collections

The booth needs a collection for each type of item it can sell or give away.

  1. Open the Booth class.
  2. Add a private list for each booth item type.
  3. Initialize each list in the Booth constructor.
  4. Add references and using directives as needed.

Design note: The lists represent booth inventory. Keep them controlled by the Booth class. Later, methods such as SellTicket and GiveFreeMap will decide when items leave these lists.

4. Create Booth Inventory

Inside the Booth constructor, use loops to create the starting inventory.

  1. Create five coupon books.
  2. Create ten maps.
  3. Create five tickets.
  4. Create five water bottles.
  5. Give each ticket and water bottle a unique sequential serial number.

Required Values

  • Coupon books are made today and expire one year after today's date.
  • Maps are issued today and weigh 0.5 pounds.
  • Tickets cost $15 and weigh 0.01 pounds.
  • Water bottles cost $3 and weigh 1 pound.

5. Use DateTime Carefully

Use DateTime.Now or another appropriate DateTime value when creating maps and coupon books.

  1. Do not hard-code dates.
  2. Do not store one shared local DateTime variable for all maps and coupon books unless your instructor tells you to.
  3. Create date values where the object is created so you can clearly see when each object was initialized.

Tip: DateTime.Now.AddYears(1) can be used to create an expiration date one year in the future.

6. Remove Hard-Coded Price Values from the Constructor

The ticket and water bottle prices should be provided to the booth rather than buried as repeated values throughout the constructor.

  1. Add a water bottle price parameter to the Booth constructor.
  2. Add a water bottle price parameter to the Zoo constructor if the zoo creates the booth.
  3. Use the booth's price property when creating water bottles.
  4. Keep ticket price handled consistently through the zoo and booth constructors.
IMAGE PLACEHOLDER: Class diagram showing Zoo constructor passing ticketPrice and waterBottlePrice to Booth.

OOP reminder: A constructor should leave an object ready to use. If a booth needs prices in order to create inventory, require those prices when the booth is created.

7. Inspect the Inventory in the Web App

The original assignment used a WPF debugger breakpoint. In this web version, you can still use the debugger, but the browser can also help show current state.

  1. Set a breakpoint in the Booth constructor after the loops.
  2. Run Zoo.Web.
  3. Inspect the booth lists in the debugger.
  4. If the dashboard already displays inventory counts, confirm the counts in the browser as well.
