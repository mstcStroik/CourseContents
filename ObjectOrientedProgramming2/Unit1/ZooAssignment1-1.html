Zoo 1.1, Part 1: Project Organization

ASP.NET Core web app version

In this part, you will clean up the starter solution and begin separating the zoo application into class library projects. The goal is to make the code easier to understand, reuse, and extend while keeping the ASP.NET Core web app as the browser-facing project.

You will work in the provided ZooWeb1.1 solution. The web project is Zoo.Web.

Topics Covered

  • Multi-project solutions
  • Namespaces
  • using directives
  • Project references
  • Debug and Release builds
  • Abstraction through project and namespace organization

OOP reminder: Abstraction means naming the important ideas in the problem. When you create projects and namespaces such as Zoo.Foods, Zoo.Animals, and Zoo.People, you are grouping related concepts so the solution communicates its design.

1. Review the Web Application

  1. Open the provided ZooWeb1.1.sln solution in Visual Studio.
  2. Set Zoo.Web as the startup project if it is not already selected.
  3. Run the application and confirm that the zoo dashboard opens in a browser.
  4. Review the starter files in Pages/Index.cshtml, Pages/Index.cshtml.cs, and Services/ZooStateService.cs.

Check Your Work

  • The solution opens in Visual Studio.
  • Zoo.Web runs in the browser.
  • You can identify the Razor page and PageModel used for the dashboard.

2. Remove Unused Using Directives

Visual Studio may add using directives that a file does not need. Clean files are easier to read and make dependencies easier to see.

  1. Remove and sort unused using directives in every class file in the solution.
  2. Include web files such as Index.cshtml.cs and service files such as ZooStateService.cs.
  3. Build the solution.

Check Your Work

  • The solution builds successfully.
  • No compiler errors or warnings were introduced while removing using directives.

3. Add a Debug Build Indicator

The original desktop assignment added [DEBUG] to the WPF window title. In the web version, display a visible debug indicator on the page when the application is running in a Debug build.

  1. Open Pages/Index.cshtml.cs.
  2. Use a compiler directive to set the existing IsDebugBuild property when the project is built in Debug mode.
  3. Open Pages/Index.cshtml and confirm that the page displays the debug indicator when IsDebugBuild is true.
#if DEBUG
    this.IsDebugBuild = true;
#endif

Tip: Compiler directives are often written at the far left margin. This makes them stand out from ordinary C# code.

Check Your Work

  • Run the web app in Debug mode and confirm that [DEBUG] appears on the page.
  • Run or publish in Release mode and confirm that [DEBUG] does not appear.

4. Create the Foods Class Library

The starter code contains business classes that should not remain bundled together forever. Begin by moving food-related code into its own class library.

  1. Create or use the existing class library project named Zoo.Foods.
  2. Move the Food class into Zoo.Foods.
  3. Change the namespace of Food to Zoo.Foods.
  4. Add project references and using directives where needed.

Check Your Work

  • Zoo.Foods builds successfully.
  • The full solution builds successfully.

5. Create the Contracts Class Library

Interfaces describe what an object can do. Move the shared interfaces into their own project so multiple domain projects can depend on them.

  1. Create a class library named Zoo.Contracts.
  2. Move IEater, IMover, IHatchable, and IReproducer into Zoo.Contracts.
  3. Change each interface namespace to Zoo.Contracts.
  4. Add a reference from Zoo.Contracts to Zoo.Foods if an interface uses Food.
  5. Add using Zoo.Foods; where needed.

OOP reminder: An interface is an abstraction. Code that uses IEater can work with anything that eats without knowing the exact class.

Check Your Work

  • Build Zoo.Foods.
  • Build Zoo.Contracts.
  • Fix missing references, namespaces, or using directives before continuing.

6. Create the Remaining Domain Projects

Continue separating related classes into class libraries. Your instructor may provide an exact package diagram. Use that diagram as the source of truth.

Suggested Project Structure

  • Zoo.Animals: Animal, Bird, Mammal, Dingo, Hummingbird, Platypus
  • Zoo.People: Guest, Employee, Wallet
  • Zoo.Facilities: Zoo, Booth, BirthingRoom, Restroom, VendingMachine
  • Zoo.Toys: WuvLuv
  1. Create each class library project.
  2. Move the appropriate class files into each project.
  3. Change namespaces so they match project names.
  4. Add project references as compiler errors identify missing dependencies.
  5. Add using directives as needed.

Recommended Build Order

  1. Zoo.Foods
  2. Zoo.Contracts
  3. Zoo.Animals
  4. Zoo.People
  5. Zoo.Toys
  6. Zoo.Facilities
  7. Zoo.Web

Common error: A metadata file error often means a project lower in the dependency chain did not build. Build from the bottom of the dependency chain upward.

Final Check for Part 1

  • Every class library builds successfully.
  • Zoo.Web builds and runs in the browser.
  • Namespaces match the projects where the classes now live.
  • Project references point in the correct direction.
  • The web project is responsible for browser interaction, not core zoo business rules.
